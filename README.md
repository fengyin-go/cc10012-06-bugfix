# 多维数据探查分析工具

离线版多维数据探查分析工具，涵盖数据源接入、交互查询、聚合统计、图表看板、预警通知与数据导出，所有分析配置与结果持久化到浏览器本地存储。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `data-explore-studio:entries` 这一项，或调用 `resetModule(模块)`。

## 清单导出与可回读清单数据表

导出不再用裸逗号拼接（接入地址里的逗号会冲掉字段边界），而是走 `frontend/src/data/csv.ts`
与 `frontend/src/data/manifest-store.ts`：

- **分隔规则随文件标注**：每个导出文件首行是 `# 分隔规则声明:` 注释行，写明实际分隔符
  （数据含逗号时自动改用 Tab 等安全分隔符）、是否双引号转义与列数。
- **两种旧读法都能回读**：`parseCsvQuoted`（RFC 4180 转义读法）与 `parseCsvFixed`
  （固定分隔符读法）逐行核对列数，任一不一致就拒绝落盘；单元格内真实换行拍平成字面量
  `\n`，空字段保留空列，跨行文本与空字段同时出现也不会串列。
- **单份清单数据表**：导出结果持久化在 localStorage 的 `data-explore-studio:manifests`
  下，每个模块只保留一份。重试 / 并发写入按内容校验和幂等复用，写操作经同一把锁串行化；
  版本冲突（已确认/已归档清单上内容变更）按校验和比较取舍，内容相同沿用版本、不同才升版本
  并打异常标记。
- **生命周期顺序流转**：`已生成 → 已确认 → 已归档`，跳步与回退一律拒绝；撤销/驳回类
  动作只在同一份清单上打异常标记，不改变阶段。归档内容包含完整文件原文、两种读法回读结果
  与字段质量（行数、列数、每列非空计数、含逗号/跨行单元格数）。
- **下游引用**：数据导出页与数据集管理页直接读取数据源接入模块落库的清单数据表，
  下载入口不再现场重拼，保证导出文件、清单记录与页面明细三方一致。
- 核对脚本：`node tests/run-checks.mjs`（内存存储，覆盖逗号边界、跨行/空字段、并发幂等、
  生命周期与版本冲突等 16 项）。
